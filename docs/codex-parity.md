# Codex capability parity

This matrix describes Delamain's local Codex port. Hook dispatch was checked with **Codex CLI 0.160.0**
using a deterministic localhost Responses provider, the declared manifest, isolated homes and fixture roles.
No model or private app transport was used. Platform documents describe supported interfaces; fixture tests
prove the listed local paths, not a live Desktop installation. Watchdog transport controls use fixtures; an earlier
scratch app-server probe observed same-thread queue activation. Reachability of actual Desktop hubs through the
standalone CLI remains unconfirmed. See [installation and operation](codex.md).

## Source and verification distinctions

The [official hooks reference](https://learn.chatgpt.com/docs/hooks#tool-coverage) documents local tool coverage,
canonical payloads, matcher aliases, hosted-tool exclusion and the missing stdin pre-hook. Actual names above
come from CLI captures rather than inference from that documentation. Namespace concatenation is version-specific;
re-run the runtime controls when upgrading Codex.

`bash tests/t_codex_hook_runtime.sh` runs the real CLI against a local fixture provider when installed; it reports
SKIP without a CLI. `CODEX_HOOK_EVIDENCE_DIR=/absolute/scratch/path` retains hook captures and fixture requests.
The test checks the manifest's real dispatch, policy denials before command/patch side effects, positive controls,
TOML effort discovery, harmless messaging/stdin and delayed completion. It completes two native child turns through the fixture provider; it does not prove an authenticated
Desktop session or a real-model agent turn. Adapter tests cover legacy aliases and look-alikes
that the current catalog does not expose. Hook trust must be enabled; changing definitions requires renewed
trust in reviewed mode. No enforcement claim is made for an event the runtime does not emit.
