## Native Windows Desktop transport

Apply this transport section only on a native Windows host using PowerShell. Linux and macOS sessions, including WSL workers, follow the original skill body below with its original commands and paths.

Continue in this current native Codex chat. SessionStart gives its real session UUID and the installed bridge path. In PowerShell invoke `& '<plugin-root>\windows\desktop.ps1' --session-id '<current UUID>' <original-tool> <args>` for each original Delamain command. Preserve all planning, delegation, locks, waits, reporting, and handoff rules below.

For original Bash instructions use `& '<plugin-root>\windows\desktop.ps1' --session-id '<current UUID>' shell '<literal Bash source>'`. Double each single quote inside the PowerShell single-quoted source. The source and bridge path must be literal strings: do not build the Bash program with PowerShell variables, expressions, or expandable strings. Hooks inspect recognized literal paths ending in `desktop.ps1` (direct or `&` invocation) and apply the original gates to their literal Bash source. This is advisory coverage, not a security boundary: variable paths such as `$b='<path>\windows\desktop.ps1'; & $b shell ...`, aliases, expressions and wrappers are outside recognition and have no exact-source guarding guarantee. A recognized literal bridge path with nonliteral arguments is refused. Multiple literal calls separated by semicolons are supported; set the native tool's `workdir` when they need a different directory. A single call can use `shell --cwd '<Windows or Linux directory>' '<literal Bash source>'`.

Paths returned by original tools are Linux paths. Before using one in a native file tool or native `workdir`, run `& '<plugin-root>\windows\desktop.ps1' --session-id '<current UUID>' path --windows '<Linux path>'` and use the returned Windows drive or WSL UNC path. The inverse is `path --linux '<Windows path>'`. This also applies to worktrees and handoff files. Run Git through the bridge Bash: worktrees created by the original tools contain Linux Git pointers that native Windows Git cannot resolve. Native editors and build tools can use converted paths. Read and edit Linux home files through the converted UNC path or the literal bridge shell. Do not start another WSL coordinator chat. WSL must be running and accessible; this transport does not add coverage for hosted tools or `write_stdin`.
